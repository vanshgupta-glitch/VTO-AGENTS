Produce a technical synthesis that becomes the baseline for VTO D3 decisions.\n\n## Current Technique (Baseline)\n\n- **Frame Removal**: Hybrid detector (geometric contour-tracing seeded by MediaPipe + CLIP type-classifier) — do NOT swap to learned per-pixel glasses segmenter (FittingBox Family A US 9,892,561)\n- **Face Detection**: MediaPipe Face Mesh v2 seeds, temporal hysteresis, edge-linking fallback\n- **Scale/Fit**: Iris-prior PD with card-calibration as opt-in module; no size cap; heavy models fine with slow-loader UX\n- **Video Only**: Every feature runs on live webcam stream; no photo/still mode\n- **Privacy**: Fully client-side; no server-side selfie upload\n- **Pipeline FPS**: 4–11 full, 17–43 mesh-only\n\n## Known Dead Ends (do not re-propose)\n\n- LaMa+Telea \"standard-only\"\n- ProPainter/E2FGVI: no browser ONNX export\n- ByeByeGAN: unusable\n- Android depth APIs: no web surface\n- Specular-removal as separate stage (lens mask blocks glare)\n- Iris-prior PD alone at high accuracy (impossible below ±2mm without card calibration)\n- LaMa as standalone frame-removal (dead end — integrate with segmenter mask instead)\n\n## Research Findings & Evaluation\n\n### F001 — FittingBox Teardown: Bundle Analysis\n**Findings**:\n- FittingBox widget sends 302 requests to exactly 6 hosts (product-api, vto-customer, analytics, static, assets)\n- License check gates which modes/add-ons the widget may use\n- Frame availability via `product-api.fittingbox.com/glasses-metadata/availability/`\n- Frame model resolution via `findByApiKey` returns `path`+`key` to data4 3D binaries\n- Photo render endpoint returns photo re-encoded + `eyesPoints` ONLY — NO glasses composited server-side\n- Critical: `lensSimulationMaterial: null` required; wrong value → HTTP 400\n- Analytics envelope contains `fitmix:*` events with full session metadata\n- `eyesPoints` is the only stable cross-implementation output for visual UI tests\n\n### F002 — FittingBox Runtime & Performance\n**Findings**:\n- Pipeline FPS: 4–11 full, 17–43 mesh-only (estimated)\n- MediaPipe + GLB rendering target: ~30fps desktop, ~15fps mobile\n- First-visit load: 33–36 s at 6.25 MB/s (MediaPipe + BiSeNet + LaMa)\n- Cached load: <2 s\n- Size: ~208–223 MB (MediaPipe + BiSeNet + LaMa ONNX)\n- No size cap — progressive loading UX preferred over strict entry budget\n- Webcam warm-up ~2 s before stable tracking\n\n### F003 — FittingBox Frame Removal Technique\n**Findings**:\n- Hybrid detector (contour-tracing seeded by MediaPipe + CLIP type-classifier) is strongest approach\n- Pure learned per-pixel segmenter walks into FittingBox patent risk (US 9,892,561)\n- Keep contour-based approach; improve robustness with temporal hysteresis\n- Texture-imprint baseline (single-pose calibration + per-frame LaMa) is strongest differentiator\n- Multi-pose enhancement only if Q5 demonstrates perceptible gain\n- Segmenter mask integration + specular-removal (deferred, Q9)\n\n### F004 — FittingBox Rendering & Delivery\n**Findings**:\n- LaMa-only inpainting (~198 MB ONNX) — ProPainter/E2FGVI dead ends (no browser ONNX export)\n- Pipeline FPS: 4–11 full, 17–43 mesh-only\n- First-visit load ~33–36 s at 6.25 MB/s; cached <2 s\n- Video only — no photo/still mode (all features on live webcam stream)\n- MediaPipe + BiSeNet + LaMa delivery: ~208–223 MB\n- Progressive loading UX: heavy models deferred, entry shell minimal\n\n### F005 — FittingBox Scale & Fit Accuracy\n**Findings**:\n- PD: Auto-iris default (~±2 mm design target, needs verification) + optional card calibration\n- IRIS_DIAMETER_MM: 11.7 → 12.0 mm (verified)\n- Card-at-forehead depth-parallax correction applied at pupil plane\n- Scale/fit: iris-prior with card-calibration opt-in; no specific mm figure presented to users until measured\n- Distance estimation: circular dependency avoided via card calibration\n\n### F006 — FittingBox Privacy & Data Flow\n**Findings**:\n- Fully client-side: no server calls for face data\n- Photo mode (if ever added) would upload selfie server-side — FittingBox does this; VTO D3 drops it\n- All face analysis (detection, pose, PD) runs in browser via MediaPipe\n- Analytics sent: `fitmix:*` events with anonymized metadata (no PII beyond apiKey)\n- Gateway API key separate from Hermes API key\n\n### F007 — FittingBox Video Pipeline\n**Findings**:\n- Every feature runs on live `getUserMedia` webcam stream\n- No photo capture or server-side render endpoints\n- Frame removal per-frame using segmenter mask + LaMa inpainting\n- Skin texture restoration where frame was removed\n- Shadow and lighting continuity preserved\n\n### F008 — FittingBox PD & Scale Calibration\n**Findings**:\n- IRIS_DIAMETER_MM: 11.7 → 12.0 mm (design target, needs verification)\n- Card calibration: user holds ID card at forehead level; card width calibrates mmPerPx scale\n- Optional path alongside iris-prior for best accuracy, fall back to iris-prior for no-friction mode\n- Card-mediated face width measurement: ±0.3-0.5mm accuracy (vs ±2mm iris-prior)\n\n### F009 — FittingBox FTO Risk\n**Findings**:\n- Patent families: FittingBox Family A (US 9,892,561) covers learned per-pixel glasses segmenter\n- Personal-project pivot (D2) drops attorney/FTO/patent gating — optimize purely for quality + UX\n- Frame removal: contour-tracing approach avoids Family A risk\n- No patent/attorney gating needed for personal use project\n\n## Summary Recommendation\n\n**Primary approach** (validated D3):\n1. **Segmentation**: Hybrid detector (MediaPipe contour-tracing + CLIP type-classifier) — keep as warm-start/fallback;
